# Host SSH 错误解读

工具失败时只根据返回 JSON 解释，不要编造「权限必须 600」「我先跳过 agent」等未出现在结果里的原因。

## `tried`

客户端已按顺序尝试的私钥列表，每项大致含路径与结果：

| 结果 | 含义 |
|------|------|
| `missing` | 文件不存在 |
| `encrypted` | 私钥有口令；当前桌面端不弹口令框 |
| `rejected` | 服务器拒绝该钥 |
| `unreadable` | 读文件失败 |

`encrypted`：可建议用户改用无口令钥，或在本机自行 `ssh-add` 后再试（agent 有钥时 `agent` 字段会反映）。

## `agent`

| 值 | 含义 |
|------|------|
| `empty` | agent 在跑但没有可用身份 |
| `unavailable` | 无法连上 agent |
| `tried_n` 等 | 已用 agent 试过若干身份 |

## 主机密钥

- 与 `known_hosts` **不一致**：连接会断；按错误说明处理，**不要**改用系统 `ssh` 强行覆盖
- 新主机：写/删/exec 确认卡片带指纹；用户允许后写入 `known_hosts`

## 成功时

成功响应可能带 `auth` / `auth_key`，表示实际用上的认证方式；可用于向用户简短确认「已用某钥连上」，无需展开找钥过程。
