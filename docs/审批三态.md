# 审批三态（Allow once / Always allow / Deny）

日期：2026-10-10 · 状态：设计稿（未实现）· 范围：HITL 工具确认卡  
对照现状：聊天 `approval-gate-card` 仅 **批准 / 拒绝**；本机 `host_*` 已有 Auto-review 的 auto/confirm/deny 档，但**会话工具批准**尚未三态 + 按工具记忆。

---

## 1. 三态定义

| 用户选择 | 语义 | 持久化 |
|---|---|---|
| **Allow once**（允许一次） | 仅本 `request_id` / 本轮工具调用放行 | 不写记忆 |
| **Always allow**（始终允许） | 该用户（或该 Bot）下，**同类工具**自动放行 | 写入 allowlist |
| **Deny**（拒绝） | 本轮拒绝；可选「始终拒绝」见下 | 默认不持久；高级可写 denylist |

UI 主按钮建议（中文）：

- 主：`允许一次`
- 次：`始终允许`
- 危险/次：`拒绝`

不要用含糊的「批准」——与「始终允许」易混。

## 2. 作用域

| 维度 | 默认 | 说明 |
|---|---|---|
| 用户 | 是 | allowlist 按 `user_id` |
| Bot / Agent | 可选叠加 | 群内不同 Bot 可分开记 |
| 工具名 | **必选** | 至少 `shell` 族、`git` 族（见策略表） |
| 参数指纹 | 后置 | 如 `git push` vs `git status`；MVP 可只按工具族 |

MVP：**按工具族 + 用户**；不做全局「永远允许一切」。

## 3. 按工具策略表（MVP）

| 工具族 | 匹配（示例） | Allow once | Always allow | Deny | 备注 |
|---|---|---|---|---|---|
| **shell** | `host_shell`、sandbox shell、`run_terminal` | ✅ 默认主按钮 | ✅ 写入后同族 auto | ✅ | 高危命令仍可走硬拒绝（与现网 Auto-review deny 叠加） |
| **git** | 参数/工具名含 `git`；或专用 `git_*` | ✅ | ✅ 建议仅对 **只读**（`status`/`diff`/`log`）开放 Always；写操作（`push`/`commit`/`reset`）Always 需二次确认或禁用 | ✅ | MVP 可整族 Always，但文案警告「含 push」 |
| 文件写/删 | `host_write` / `host_delete` / … | ✅ | 可选 | ✅ | 可与 shell 分开 |
| 其它 tools | 默认 | ✅ | ✅（同工具名精确匹配） | ✅ | |

**叠加规则（硬）：**

1. 平台 / Auto-review **硬拒绝** > 用户 Always allow（不能放行 fork bomb 等）。  
2. 机器 `exec_policy=ask` → Always allow **降级**为 Allow once（或禁用 Always 按钮）。  
3. Deny 本轮不执行；不自动写「始终拒绝」，除非用户点「始终拒绝」（可放进 ⋯ 菜单，MVP 可不做）。

## 4. 与现网 API 对齐

现状：`POST /v1/conversations/{id}/approve` body `{ request_id, approve: bool, reason }`。

建议扩展（向后兼容）：

```json
{
  "request_id": "...",
  "approve": true,
  "decision": "allow_once" | "always_allow" | "deny",
  "scope": { "tool": "host_shell", "tool_group": "shell" },
  "reason": ""
}
```

- 旧客户端只传 `approve: true/false` → 映射为 `allow_once` / `deny`。  
- `always_allow` 时服务端写入 `user_tool_allowlist`（表或 settings JSON），后续同族 `waiting_approval` 可直接 resume。

## 5. UI

```
┌ 工具需要确认 ─────────────────┐
│ host_shell · git push origin  │
│ reason: 可能改写远程历史       │
│ [拒绝]  [始终允许]  [允许一次] │
└───────────────────────────────┘
```

- 窄屏：主按钮「允许一次」全宽；「始终允许」「拒绝」次行。  
- Always 前可 toast：「之后同类 shell 将不再询问（可在设置里撤销）」。  
- 设置 → 审核：列出 Always allow 条目，可单条撤销。

## 6. 非目标

- 不做企业级 RBAC / 审批流多级签核  
- 不在本设计实现 Team pack  
- 不替换本机 Auto-review 硬拒绝表（只叠加）

## 7. 验收（实现时）

1. 确认卡三按钮文案与顺序正确；只点「允许一次」不写 allowlist。  
2. 「始终允许」后同工具族不再弹卡；设置可撤销。  
3. 硬拒绝命令即使 Always 过仍拒绝并说明。  
4. 旧 `approve:true` 行为 = Allow once。  
5. `exec_policy=ask` 时无 Always 或点 Always 仍每轮询问。
